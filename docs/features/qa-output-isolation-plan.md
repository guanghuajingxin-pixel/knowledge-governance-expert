# 智能问答过程与答案串流问题：诊断及修复方案

2026-09-13。原始诊断及方案如下；本轮已按用户要求实现修复，交付状态见文末。

## 已确认的实际现象

检查截图对应会话的持久化记录，上一轮问题是“未遂、轻微事故调查报告需要多久提交？”，本轮是“未遂事故与轻微事故的分级认定标准分别是什么？”。本轮助手内容共 1882 字：先出现上一轮的上下文摘要（用户当前问题、已完成动作、检索结论、回答注意、node_id），随后才接上本轮分级标准的回答；尾部又扩展了提交时限、处置职责等未被本轮询问的内容。

这并非单纯答错问题或前端折叠：内部摘要和正式答复混进同一正文，而且已经落库。不能靠隐藏几行文字修复历史数据的语义混杂。

本轮保存的 steps 确实只有“问题理解”，quality.verification 为 prompt，dws 为 not_needed。上一轮则保存了完整的知识检索、钉钉检索及原文读取过程。该证据不能证明本轮执行了检索却丢失全部事件；本轮可能复用了历史正文，前端也没有“复用历史依据”的阶段说明。

## 代码依据

1. `services/deerflow/backend/app/qa_server.py` 开启 SummarizationMiddleware，12000 tokens 触发，保留最近 10 条消息。依赖中的摘要模型通过 invoke 生成上下文摘要，其输出不是本轮用户答案。
2. 同文件 `_event_stream` 接收 `stream_mode=["values", "messages"]`。messages 分支解包了 `(msg_chunk, _meta)`，却不使用 metadata 判断调用节点/用途；全部 AIMessageChunk 进入 `_buf_text`。缓冲达到 24 字、0.35 秒即可发出 ai_text，不要求先被确认成最终答复。摘要/内部模型调用的文本因此有泄漏通道。
3. 同文件的 strip_narration / NoteLineFilter 是关键词过滤；缺少截图中的多个标题，且不能可靠区分用户正文与内部摘要。即使补齐关键词，摘要仍可能换一种措辞泄漏，正常答案还可能被误删。
4. `services/kb-api/app/services/agent/deerflow_runner.py` 将收到的 ai_text 全部拼接入 answer_parts。没有 answer message ID、当前轮 ID 或用途字段，也没有替换/撤销误发内容的机制。
5. runner 仅映射 knowledge_search、dingtalk_search、dingtalk_read_doc、task 等有限工具；已有 dingtalk_browse、knowledge_context_expand 缺少对应的开始/结束映射。它固定发出“问题理解”，不展示上下文复用、摘要整理或答案生成等真实阶段。
6. runner 在有引用时，或没有检索调用时，均可设置 answered；quality.verification 明确为 prompt。`web/src/views/chat/index.vue` 却将 answered 显示为“已通过证据核验”。目前这不是经过服务端事实核验的结论。
7. enterprise-kb-qa 提示词已明确禁止检索笔记与无关内容。说明问题以输出路由和事件协议为主，提示词只能辅助约束最终表达。

## 修复顺序

### 第一优先级：隔离内部文本与正式答复

- 事件包含 conversation_id、turn_id、run_id、message_id、source_node 与用途。只允许本轮主回答节点的 answer_delta / answer_final 写入答案区；未知用途默认不展示。
- 摘要、规划、工具消息、子任务结果均作为内部状态或过程事件，不混入正文。摘要模型显式关闭面向用户的 token 推送，并给调用打用途标签；消费者仍执行白名单判断。
- 保留流式体验：在明确的答案生成阶段输出 delta，以 answer_final 的权威正文替换暂存正文，而非拼接所有 AI 消息。未生成最终答复时明确未完成，不从任意最后一条 AI 消息兜底。
- 关键词过滤仅作为异常检测；检测到内部模板、技术字段或问题不一致时不静默删几行，而是重新生成最终答复或明确失败。

### 第二优先级：恢复真实的过程状态

- 使用 step_start / step_update / step_end，按 step_id 或 tool_call_id 更新，状态为进行中、完成、失败、取消、复用。
- 展示用户有用的动作摘要：问题处理、检索知识库、读取文档、展开相邻条款、复用本会话已读依据、组织回答。提供文档数/命中数及真实结果，不展示模型私有推理。
- 补齐 dingtalk_browse、knowledge_context_expand 等工具事件；结束时只完成实际成功的步骤，不把上一个步骤无条件打勾。
- 本轮没有新检索时，只有确认复用了已读正文才显示“复用本会话资料”；不能伪造检索步骤。历史没有正文依据时需要补检索。
- 过程记录与答案共同按本轮 ID 持久化；刷新、切换会话、继续探索、停止探索后仍能准确回放。

### 第三优先级：绑定当前问题、控制答案范围

- 当前原始问题与可选检索改写分别保存，历史摘要只提供背景，不替代当前任务。新问题与 continue/stop 续跑明确区分。
- 主回答阶段将“当前问题 + 可引用正文 + 输出范围”作为输入。比较类问题默认比较表；只回答被询问的维度，额外提交时限/处罚/职责仅在理解结论必须时补充。
- 提示词增加显式规则：禁止输出用户当前问题、已完成动作、检索结论、回答注意、工具参数和原始 node_id；不复述无关召回内容；不附加泛泛的“如需……请追问”。
- 自检问题实体和回答属性是否一致；摘要里曾出现的数字/时限不自动成为当前问题的依据。

### 第四优先级：校正证据状态

- 首先将现有 prompt 自检对应的 UI 文案改为“附有参考来源”等准确表述；无来源不显示已核验。
- 如产品确需“已通过证据核验”，增加独立且可审计的核验结果：每个关键结论与引用正文对应，检查数值、条件、否定、对象和版本；不支持的结论移除或标缺口。
- 区分“回答已生成”“有引用”“关键结论已核验”，不由 answered 或引用数量直接推断核验通过。

## 验收用例

- 连续两轮分别询问“报告提交时限”与“分级标准”，触发 12000 tokens 摘要：摘要可以进入内部上下文，但任何一个摘要 token 都不得出现在答案区或最终落库正文。
- 复用历史证据与新增检索分别验证；复用过程不冒充本轮新检索，缺少正文时自动补查。
- knowledge_search、dingtalk_search、dingtalk_read_doc、dingtalk_browse、knowledge_context_expand 均有匹配的开始/完成/失败事件。
- 摘要 chunk 先于答案、晚于答案或交错返回，主答案仍只出现一次；同会话续跑、并行会话互不串台。
- 流中断、取消、模型错误、无最终答复时不回放上一轮答案、不展示成功核验。
- 对照截图，本轮只显示实际过程、两类事故认定标准与必要引用；不出现内部记录及无关提交时限。具体标准必须以原文核对，不能将不同事故类别的表格行混用。
- 刷新历史后过程和正文与当轮完成时一致。已有污染答案标记为历史异常，可显式重新生成；不自动篡改历史对话。

建议先修事件隔离与过程，再补问题范围和核验状态；无需先更换模型或重写整个智能体。

## 实施结果

- 新增 `app/qa_events.py`，以根图 model 更新的消息 ID 和最终状态确认答案；每次运行独立 ID 和历史基线。摘要、子任务及未知节点不能发布答案。messages 仅用于无正文的阶段提示。
- 移除按 24 字/0.35 秒判断“像答案就提前输出”的路径，以及旧的关键词删段过滤器。正式正文确认后一次展示，过程实时更新；此取舍避免已经流出的内部文字无法撤回。异常模板不静默拼凑为答案，而是明确失败。
- 后端只接收同轮 `answer_final`，不拼接多个模型调用；流缺少正常结束时不保存伪最终答复。新增目录浏览、上下文扩展过程，工具结果按调用 ID 更新完成/失败。已读取正文的引用被实际复用时才说明“复用本会话资料”。
- 前端步骤保存 ID 与状态，不再把所有结束步骤打勾；取消、暂停及缺少完成结果单独显示。引用标签改成“附有参考来源”，没有增加声称已核验的假状态。
- 当前问题加入明确范围约束，运行时人格追加统一答复规则，保留用户自定义人格文件。历史摘要仅作背景，比较问题不附加未问的时限/处罚/职责。
- 本次不重写既有污染历史。旧消息刷新后会使用准确的引用标签，正文需用户重新提问生成。

验证包含真实 LangGraph 的连续两轮与自动摘要、未知/跨会话事件隔离、缺失结束帧、工具失败、并行步骤与历史 JSON 回放。完整 DeerFlow 测试套件另有 12 项失败：1 项原有 client 缓存键测试、11 项缺少 Docker/provisioner 文件的测试；本次未修改这些模块。

最终验证：本次相关后端 34 项与前端 6 项测试通过，前端类型检查和生产构建通过。DeerFlow 全量为 652 通过、1 跳过、12 失败（上述未改动模块）。本地 QA sidecar 已保留原环境重启；实际模型连续两轮调用均只返回各轮一个 answer_final，kb-api 完整链路正常输出处理/分析/组织回答状态及 quality.verification=unverified。
