# 项目文档库与可替换引擎

## 页面与数据归属

知识应用 → 知识库有四个独立页签：

| 页签 | 管理对象 | 处理／检索职责 |
| --- | --- | --- |
| 文档库 | 本项目创建的库、原文件和文档记录 | RAGFlow HTTP 适配器承担解析、分段、向量化和检索 |
| 问答库 | 原有 FAQ 库、目录、问答对和批量导入 | 保持 faq-service 职责 |
| DIFY库 | 外部 Dify 数据集的镜像引用 | 可独立停止登记和卸载 Dify |
| RAGFLOW库 | 外部 RAGFlow 数据集的镜像引用 | 与本项目文档库区分展示 |

`knowledge_libraries.library_type=document` 标识项目文档库，默认 `external` 保留历史镜像；`platform` 仍用于检索路由，不能用它判断业务库归属。`library_documents` 保存项目文档记录，原文件保存到本项目 MinIO。已有 `/knowledge-bases` 文档库和历史 MinerU 流程不自动迁移，以免改变既有数据。

文档库在现有智能问答选库中单独分组；启停沿用知识库注册表的开放检索控制。本次没有改变原有系统的管理员／编辑者共享工作区权限模型，也没有新增参考站点的细粒度文档 ACL。

## 参考设计与源码依据

源码基准为 `ragflow` Git 提交 `7f09c774370dc9ae4eda91492a502dd10c9c51b3`：

- `api/apps/restful_apis/document_api.py`：上传、读取、更新、删除文档。
- `api/apps/restful_apis/chunk_api.py`：解析、停止、分段读写和检索。

## 处理流程

1. 基础信息 → 解析与分段设置 → HTTP 建库 → 在本项目登记远端 ID。
2. 上传时只保存本项目原文件和记录，状态为待解析，不立即调用远端解析。
3. 解析时上传引擎，先持久化返回的文档 ID；然后应用当前库级规则，显式 POST 启动解析。
4. 页面每 5 秒刷新正在处理的文档。引擎的 UNSTART／RUNNING／CANCEL／DONE／FAIL 和数字状态映射为待解析／解析中／已停止／已完成／失败；负进度始终判定失败。未知状态不会伪装为已完成。
5. 失败后重试复用文档 ID；正在处理时拒绝重复启动。文档操作使用库级及文档行锁，避免同一项目 API 并发修改。
6. 停止和重新解析均有明确确认，因为 RAGFlow 会清除已有分段。库设置只影响下一次解析，不自动覆盖人工校正。
7. 分段分页读取、关键词搜索、Markdown／表格安全展示；支持添加、编辑、删除、关键词、启停和 JSON 导出。新增分段接口不处理 `available`，适配器在需要停用时对返回 ID 显式更新。
8. 原文件下载不依赖 RAGFlow 在线。删除文档先删除远端文档及分段再移除项目记录，原始对象保留用于灾难恢复，后续可由存储保留策略清理。

支持通用、说明书、论文、书籍、法律、演示文稿、表格、整篇策略；DeepDOC／纯文本 PDF 解析；通用策略父子分段；关键词和问题增强。Token 长度是引擎目标值，不保证表格等结构严格按该长度拆分。增强功能会调用引擎配置的语言模型。向量模型来自引擎列表，已有索引时切换模型受引擎约束。

参考站点的知识图谱、分类标签、过期策略、审批发布、按文件类型组合策略及父子分段的独立父子编辑器不在这次实现范围，不能把普通分段编辑当作重建父子结构。FAQ 继续使用现有问答对流程，不通过 RAGFlow 重新解析。

## 升级、卸载与恢复

- RAGFlow 作为独立 HTTP 服务升级。源代码目录只是参考，运行本项目无需把该目录加入 Python 路径。
- 当前源码使用 PATCH 更新文档／分段；适配器只在确定返回 HTTP 405 时兼容旧版 PUT。网络超时或 5xx 不自动重放写操作。
- 记录建库连接地址。解析和检索均校验绑定，阻止切换系统连接后向另一实例发送旧库请求。凭据仍由现有系统配置管理，不在文档库记录内复制密钥。
- 卸载 Dify 不影响项目文档库。卸载 RAGFlow 会停止这些库的解析及检索能力；需要先导出，不能承诺卸载后继续使用同一索引。
- 文档库详情的“导出归档”生成 ZIP：`manifest.json`（版本、库信息、解析配置）、`originals/<文档ID>/<文件名>`、`chunks/<文档ID>/<页码>.json`。包含未解析／失败文档的原文件；解析进行中拒绝导出。导出分段需要引擎在线。
- 替换引擎时实现同一适配边界、从原文件重建索引，或消费导出的分段恢复人工校正。本次提供可移植导出，不提供自动迁移导入或向量索引格式转换。
- 远端建库成功但本地登记失败时，接口报告已创建数据集 ID，便于恢复；不静默重复创建。跨两个系统没有分布式事务，写操作超时后应先检查远端状态。

## 验证与部署

迁移：`uv run alembic -c ../../alembic.ini upgrade head`，新增 `0033_managed_document_libraries`，历史镜像默认为 external。

单元测试：在 `services/kb-api` 执行 `uv run python -m unittest discover -s tests -p test_managed_libraries.py`。前端执行 `pnpm run build`。

实际连接验证：建库、上传中文文件、解析、状态刷新、分段编辑／停用／启用、检索命中、原文件与分段 ZIP 导出。默认云端 embedding 曾返回余额不足；改用已配置的 `bge-m3@mac-mini@Xinference` 后解析成功。RAGFlow 索引更新是近实时的，编辑后立即查询可能短暂返回旧值。
