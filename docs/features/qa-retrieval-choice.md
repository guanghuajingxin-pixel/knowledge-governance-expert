# 知识库证据不足后的可选钉钉探索

更新日期：2026-09-13。保持现有 DeerFlow sidecar 主链路，不新增数据库字段。

## 用户流程

1. 先检索企业知识库。证据充分时直接回答，不自动扩展钉钉。
2. 证据不足时，先展示当前原文内容总结、未覆盖要点、置信度与评分原因，再展示“继续从钉钉知识库探索”和“基于知识库内容回答”。首次选择没有自动续跑倒计时。
3. 选择继续后才授权本轮的钉钉搜索、目录浏览与正文读取。选择基于知识库回答则停止检索，使用同一轮已有上下文整合答案，缺失部分明确说明。
4. 用户同意钉钉探索后开始计时：约 60 秒未完成时进入原有延时探索选择；继续后 300 秒再次选择，累计探索 600 秒硬停止。等待用户选择的时间不计入探索预算。延时阶段沿用原来的 10 秒自动续跑交互，首次钉钉授权不自动续跑。

## 分数含义

置信度表示模型对“现有知识库证据能否完整回答原问题”的评估，不是正确概率、向量相似度或经专家校准的准确率。证据不足阶段约定范围为 0–69，服务端限制异常评分；没有可用正文时强制为 0，并覆盖任何虚构的内容总结。页面同时显示原因和未校准说明。

摘要通过澄清工具的结构化参数产生，仅总结实际返回的知识库正文。模型若沿用旧提示直接要求钉钉工具，执行层先确保知识库检索，再转为选择卡片；缺少有效摘要时展示明确标记的原文摘录与保守评分，不假装已完成语义评估。

## 实现与边界

- `ExplorationTimeoutMiddleware` 维护本轮授权与计时状态，`kb_tools` 在每次钉钉网络请求前检查授权及剩余预算。新问题重置授权，停止或取消后拒绝钉钉访问；不依赖模型遵守提示词。
- 长操作结束后在模型边界触发延时选择，钉钉 HTTP 请求的等待上限受剩余预算限制。它不是独立后台任务调度器；模型/上游正在执行时，按钮可能略晚于 60 秒显示。
- 必需的来源选择使用 `ask_clarification`，不会因关闭可选澄清工具而失效。
- SSE 的 `choice_pause` 携带 `choice_kind`、`evidence_summary`、`confidence`、`confidence_reason`、`citations`。JSON 接口同样返回 `awaiting_choice`，不返回空响应。API 及侧车连接时限覆盖原有延时探索预算。
- 正常结束或等待选择时，API 与侧车均保留续跑状态；只有未正常结束的连接才执行取消清理。否则首次卡片虽然显示正常，下一次点击会被当作已取消的请求。
- 前端按摘要、评分、按钮的顺序呈现；修复等待确认状态未触发响应更新导致按钮仍被禁用的问题。
- 摘要、评分与选择卡片存入现有消息 detail，刷新会话可恢复；历史旧卡片不重复授权。关闭会话记忆时，同一问题的选择仍复用其独立线程，下一问题新建线程。
- 暂停状态沿用 sidecar 进程内注册表。服务重启、状态淘汰后明确提示重新提交原问题，不把旧选择当作新的问题或自动授权。需要跨进程/多副本恢复时应另行迁移到共享状态存储。

## 验证

新增真实 LangGraph 回归覆盖“旧提示词请求钉钉 → 先查知识库 → 暂停 → 用户选择基于知识库回答”，确认没有钉钉调用；模拟时钟验证首次 60 秒和续跑 300 秒、等待时间排除、新问题授权重置。工具测试验证三个钉钉入口未经同意均不发网络请求。

前端组件测试通过实际点击两个按钮检查动作与会话参数，并用模拟时钟验证首次选择超过旧倒计时仍不会自行继续，检查摘要、评分和持久化数据。另覆盖 JSON/SSE 选择事件、关闭会话记忆后的续跑线程。

本地回归：侧车 31 项、API 路由 10 项及 runner 12 项通过；前端 19 项测试及生产构建通过。跨 HTTP 连接测试检查暂停后再次继续仍有授权，以及过期选择返回明确错误。

浏览器实测：以无对应规范的审批人问题触发证据不足，页面先展示总结、5/100 评分及两个可点击选项；确认后才出现钉钉检索，正常完成并明确无法确认审批人，没有再发生续跑连接中断。本轮探索在 60 秒内完成，60 秒延时分支由模拟时钟回归验证，未在该次实测中触发。
