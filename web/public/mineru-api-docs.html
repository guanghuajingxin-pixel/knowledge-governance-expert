快速开始（60 秒跑通）

一次完整的解析 = 三步上传 拿到 file_id → 创建解析任务 → 轮询 至终态 → 下载产物：

BASE=http://127.0.0.1:8010

# ① 创建上传会话（只声明文件元信息，不传内容）
curl -s -X POST $BASE/v1/uploads -H 'Content-Type: application/json' \
  -d '{"filename":"demo.pdf","bytes":123456,"mime_type":"application/pdf"}'
# → {"id":"upload_xxx","status":"pending","upload_url":".../content",...}

# ② PUT 原始字节（Content-Type 与 mime_type 保持一致）
curl -s -X PUT $BASE/v1/uploads/upload_xxx/content \
  -H 'Content-Type: application/pdf' --data-binary @demo.pdf

# ③ 完成上传 → 得到 file_id
curl -s -X POST $BASE/v1/uploads/upload_xxx/complete \
  -H 'Content-Type: application/json' -d '{}'
# → {"status":"completed","file":{"id":"file-yyy",...}}

# ④ 创建解析任务（引用 file_id）
curl -s -X POST $BASE/v1/parse/jobs -H 'Content-Type: application/json' \
  -d '{"files":[{"source":{"type":"file_id","file_id":"file-yyy"}}],
       "ocr_mode":"auto","output_formats":["markdown","middle_json"]}'
# → {"job_id":"job_zzz","status":"queued",...}

# ⑤ 轮询任务直至终态（completed / partial / failed / canceled）
curl -s $BASE/v1/parse/jobs/job_zzz

# ⑥ 按产物引用下载 markdown / middle_json
curl -s $BASE/v1/files/file-mdout/content > result.md
浏览器无法直连该服务（不带 CORS 头），前端请经 kb-api 同源代理调用，见 前端集成。

全局约定

条目说明
Base URL默认 http://127.0.0.1:8010；可在「解析引擎 → 自定义解析」页签顶部配置（localStorage 持久化）
鉴权本地服务无鉴权，任何请求不需 API Key
请求体JSON 接口必须显式带 Content-Type: application/json；文件字节接口用 application/octet-stream / 具体 MIME
时间字段Upload / File 对象的 created_at、expires_at 为 Unix 秒；Job 对象的 created_at 等为 ISO 8601 字符串
错误结构4xx/5xx 统一返回 {"error":{"message":"具体原因","type":"...","param":null,"code":null}}，取 error.message 展示
ID 前缀上传会话 upload_*、文件 file-*、任务 job_*
产物格式本项目固定输出 markdown + middle_json（服务亦支持 html / latex / docx / zip 等）

返回可选档位及当前绑定的模型，建任务时作为 tier 传入；缺省 = 服务端默认。

tier含义

# → {"object":"list","data":[{"id":"flash","description":"...","current_model":"..."},...]}

文件上传（三步协议）

与 OpenAI Files 一致的分步协议：声明元信息 → 传原始字节 → 提交完成。三步缺一不可。

POST/v1/uploads第 1 步 · 创建会话

字段类型必填说明
filenamestring是文件名（含扩展名，用于类型识别）
bytesinteger是文件精确字节数（>0），第 2 步按此校验
mime_typestring是如 application/pdf、image/png
purposestring否parse（默认，待解析）/ input_image
sha256sumstring否64 位十六进制摘要，complete 时校验一致性
expires_afterobject否{"anchor":"created_at","seconds":3600}，3600–2592000 秒

响应关键字段：id（会话 ID）、status:"pending"、upload_url（第 2 步地址）、upload_method:"PUT"、upload_headers（应回传的头，含 Content-Type）、expires_at。

PUT/v1/uploads/{upload_id}/content第 2 步 · 传字节

  • 请求体为原始二进制（curl 用 --data-binary @file），不是 multipart/form-data
  • Content-Type 必须与第 1 步 mime_type 一致（直接照抄响应里的 upload_headers 最稳）
  • 错误：404 会话不存在 · 409 会话已完成/已取消 · 413 字节数与 bytes 不符或超上限

POST/v1/uploads/{upload_id}/complete第 3 步 · 完成

请求体可为 {} 或 {"sha256sum":"..."}（服务端校验）。响应 status:"completed"，其中 file.id 即解析任务引用的 file_id。

会话辅助接口

  • GET/v1/uploads/{upload_id} — 查询会话状态（pending / completed / cancelled / expired）
  • POST/v1/uploads/{upload_id}/cancel — 取消未完成会话
会话默认 1 小时过期（expires_at）；complete 之后不可再 PUT；bytes 不准是最常见的 413 原因。

解析任务

POST/v1/parse/jobs创建任务（异步）

字段类型必填说明
filesarray是1–100 个 {source, page_range?}；多文件合并为一个任务
files[].sourceobject是四种来源（按 type 判别）：
  • {"type":"file_id","file_id":"file-..."} — 上传产物，推荐
  • {"type":"url","url":"https://..."} — 远程文件
  • {"type":"inline","name":"x.md","data":"..."} — 内联文本
  • {"type":"local","path":"/data/x.pdf"} — 服务端本地路径
files[].page_rangestring否页码选择，见 page_range 语法，仅对 PDF 生效
ocr_modestring否auto（默认）/ txt 仅内嵌文字层 / ocr 强制 OCR（扫描件）
output_formatsarray否默认 ["markdown"]；本项目传 ["markdown","middle_json"]
tierstring否flash / basic / standard / advanced，缺省为服务端默认
callbackobject否完成回调配置（可选）

响应（JobAsyncResponse）：job_id、status、created_at（ISO）、tier、output_formats、progress:{completed,failed,total}、files[]（含 output_files 产物引用）、links:{self,cancel}。

GET/v1/parse/jobs任务列表

返回 {object:"list", data:[{job_id,status,created_at,file_count}], has_more, first_id, last_id}，用于把服务端历史任务合并进本地队列（仅列表级信息，详情需再查单个任务）。

GET/v1/parse/jobs/{job_id}轮询状态 / 进度 / 产物

  • 建议 2 秒间隔轮询；status 进入 completed / partial / failed / canceled 即停止
  • 进度按 progress:{completed,failed,total} 计算：已处理数 = completed + failed
  • 每个文件的结果在 files[].output_files：{markdown:{file_id,bytes}, middle_json:{file_id,bytes}, zip?...}，凭 file_id 去下载
  • 单文件失败原因在 files[].error.message；耗时与模型在 files[].parse:{duration_ms,model_used,parser_version}

DELETE/v1/parse/jobs/{job_id}取消任务

仅 queued / running 可取消，返回 {job_id, status:"canceled", canceled_at}；终态任务返回 409。

文件与产物下载

GET/v1/files/{file_id}/content下载产物内容

直接返回文件原文（不是 JSON 包装）：markdown 产物为文本，middle_json 产物为 JSON。file_id 来自任务详情的 output_files.*.file_id。

# 下载 markdown 产物
curl -s http://127.0.0.1:8010/v1/files/file-mdout/content -o result.md
# 下载结构化中间 JSON
curl -s http://127.0.0.1:8010/v1/files/file-jsout/content -o middle.json

其他文件接口

  • GET/v1/files — 文件列表（含源文件与产物文件）
  • GET/v1/files/{file_id} — 文件元数据（bytes / filename / sha256sum）
  • DELETE/v1/files/{file_id} — 删除文件资源
markdown 内引用的图片通常打包在 zip 产物内（相对路径），仅下载 markdown 文本时图片不可见；base64 内联图则随文本返回。

用量查询 · GET/v1/usage

返回当前周期解析用量与限额（页数 / 文件数等），可用于页首配额提示。无请求参数。

状态机速查

对象状态流转
解析任务 Jobqueued → running → completed / partial（部分文件失败）/ failed / canceled
任务内文件queued → running → completed / failed
上传会话 Uploadpending → completed / cancelled / expired

page_range 语法（PDF 页码选择）

  • 1 起始、闭区间，逗号分隔多段："1-5,8"
  • r1 = 最后一页、r3-r1 = 倒数第 3 到最后一页；"all" = 全部页
  • 选择会自动排序去重，越界页忽略；空白 = 未指定（全部）
  • 非法：倒序区间（5-1）、~、负数页码 → 400

端到端脚本（可直接保存为 .sh）

#!/usr/bin/env bash
set -e
BASE=http://127.0.0.1:8010
FILE=$1; NAME=$(basename "$FILE"); SIZE=$(stat -f%z "$FILE")
MIME=$(file --brief --mime-type "$FILE")

# 1) 会话
UP=$(curl -s -X POST $BASE/v1/uploads -H 'Content-Type: application/json' \
  -d "{\"filename\":\"$NAME\",\"bytes\":$SIZE,\"mime_type\":\"$MIME\"}")
UID_=$(echo "$UP" | python3 -c 'import json,sys;print(json.load(sys.stdin)["id"])')

# 2) 字节
curl -s -X PUT "$BASE/v1/uploads/$UID_/content" -H "Content-Type: $MIME" --data-binary @"$FILE" >/dev/null

# 3) 完成 → file_id
FID=$(curl -s -X POST "$BASE/v1/uploads/$UID_/complete" -H 'Content-Type: application/json' -d '{}' \
  | python3 -c 'import json,sys;print(json.load(sys.stdin)["file"]["id"])')

# 4) 建任务
JOB=$(curl -s -X POST $BASE/v1/parse/jobs -H 'Content-Type: application/json' \
  -d "{\"files\":[{\"source\":{\"type\":\"file_id\",\"file_id\":\"$FID\"}}],\"ocr_mode\":\"auto\",\"output_formats\":[\"markdown\",\"middle_json\"]}")
JID=$(echo "$JOB" | python3 -c 'import json,sys;print(json.load(sys.stdin)["job_id"])')

# 5) 轮询
while :; do
  ST=$(curl -s $BASE/v1/parse/jobs/$JID | python3 -c 'import json,sys;print(json.load(sys.stdin)["status"])')
  echo "status: $ST"; case $ST in completed|partial|failed|canceled) break;; esac; sleep 2
done

# 6) 下载 markdown 产物
MDID=$(curl -s $BASE/v1/parse/jobs/$JID \
  | python3 -c 'import json,sys;print(json.load(sys.stdin)["files"][0]["output_files"]["markdown"]["file_id"])')
curl -s $BASE/v1/files/$MDID/content -o "${NAME%.*}.md"
echo "done → ${NAME%.*}.md"

前端集成（本项目）

服务不带 CORS 头，浏览器直连会被拦截；本项目统一经 kb-api 同源代理 /api/v1/mineru/* 转发，目标地址由 X-Mineru-Base 请求头指定，代理需 admin / super_admin JWT。

// 例：创建解析任务（axios 实例已带 Authorization: Bearer <jwt>）
await request({
  url: '/mineru/v1/parse/jobs',          // 实际命中 kb-api /api/v1/mineru/v1/parse/jobs
  method: 'POST',
  headers: { 'X-Mineru-Base': 'http://127.0.0.1:8010' },
  data: {
    files: [{ source: { type: 'file_id', file_id: 'file-...' } }],
    ocr_mode: 'auto',
    output_formats: ['markdown', 'middle_json'],
  },
})
  • 代理路径：/api/v1/mineru/{MinerU 原路径}，方法 / 查询串 / 请求体原样透传
  • 大文件上传 / 产物下载代理超时 300s；前端参考实现：ParserCustomTab.vue → api() / uploadOne()
  • axios 对字符串 body 不会自动设 Content-Type，必须显式加 application/json，否则 MinerU 返回 400

常见错误排查

现象原因与处理
400JSON 请求未带 Content-Type: application/json（预序列化 body 最易踩）；或 page_range 语法非法
413声明 bytes 与实际字节数不一致；或文件超过大小上限
409会话已完成后再 PUT；或对终态任务执行 DELETE 取消
404ID 拼写错误；或上传会话已过期（默认 1 小时）
CORS 报错浏览器直连被拦截 → 改走 kb-api 代理 /api/v1/mineru/*
轮询中断网络抖动连续失败应熔断并提示「从服务端拉取」恢复，避免错误刷屏
