PHILOSOPHY

设计理念

五个原则，贯穿产品的每一次检索、每一句回答、每一个配置项

💡

答案优先，而非链接堆砌

知识类问题主动、同时检索 Dify 与钉钉双来源，穷尽同义词 / 上下位词 / 拆解子问题等 3-5 轮关键词替换策略，归纳合并去重后，第一句就是实质答案，参考文档仅作补充。

🧭

先预判目录，再进目录

模拟真人查资料：先浏览知识库目录地图预判问题最可能落在哪个知识库与目录，再进入目录优先精读在线文档，每读完一篇立即判断能否作答——能答即停，拒绝无差别遍历。

⏱

把时间还给用户

检索满 1 分钟主动询问、5 分钟再问、10 分钟兜底收尾，由中间件确定性触发而非依赖模型自觉；回答随时一键中断，检索过程全程可展开回溯，Token 消耗透明可见。

🎛

一切皆可配置

智能体人格（SOUL.md）、问答技能（SKILL.md）、工具开关、任务规划 / 子智能体 / 长期记忆、模型供应商与超参，全部在后台在线编辑，保存即热生效，新对话立即应用。

🛡

安全与稳定是默认值

API Key / AppSecret 脱敏展示、加密落库，所有配置项连通性测试通过才允许保存；sidecar 不可用时自动回退内置工作流，密钥走数据库而非明文环境变量。

🪞

基于正文作答，拒绝猜测

文件名与目录只用于「该不该读」的预判，答案必须基于文档正文：pptx / docx / pdf 等办公文档由 MinerU 引擎秒级解析为 Markdown 后精读，钉钉命中文档必读正文再作答。

HIGHLIGHTS

技术亮点

不止于「能用」，每一处都是工程化的确定性设计

✓
进程内嵌入式 DeerFlow 2.0

以官方 DeerFlowClient 直接驱动 Lead Agent（中间件链 + 子智能体 + 检查点），无需 langgraph server / gateway，独立 sidecar 解决 Python 3.12 与主服务依赖隔离。

✓
混合检索管线

kNN 向量 + BM25 全文 + RRF 融合排序 + bge-reranker-v2-m3 重排，BGE 模型进程内单次加载、跨服务复用，兼顾质量与内存。

✓
企业检索工具链「四件套」

knowledge_search（Dify 检索）/ dingtalk_browse（目录地图与列表）/ dingtalk_search（文件名补漏）/ dingtalk_read_doc（正文读取），SOUL 规定检索纪律。

✓
办公文档正文秒级可读

pptx / docx / xlsx 走 MinerU 原生 OOXML 转换（秒级、无需模型），PDF / 扫描件走 pipeline OCR，本地即时解析与云 API 多级降级兜底。

✓
确定性的限时探索

中间件在模型调用边界短路合成询问，到点动作不依赖模型自觉、不额外消耗 Token；阈值可用环境变量覆盖。

✓
真正可中断的问答

前端 abort + 后端 cancel 双保险，worker 线程注入 GeneratorExit 确定性停图并释放锁，中断后立即发起新问答零卡顿。

✓
输出干净的答案正文

过渡独白与规划段落过滤、引用按答案正文反向过滤（只列真正提及的文档），第一句话就是用户要的答案。

✓
优雅回退与自愈

sidecar 不可达自动回退内置 LangGraph 工作流（分类 → 改写 → 检索 → 判定 → 生成）；定时统计错过后启动自动补跑。
